# DGM 如何让后代程序继续参与自修改

编程智能体修改自身后，新版本能否继续帮助它改代码？Darwin Gödel Machine（DGM）让后代程序参与自修改，并保存多个历史版本供后续搜索。

## 同一个程序承担解题与自修改

在任务评价中，程序修复代码仓库中的问题或完成编程任务；在自修改中，程序读取修改请求，调整自身工具和工作流程。系统从历史版本中选择出发点，执行修改，再通过编程任务评价新版本。

可继续使用的程序以代码形式保存在档案里。暂时不占优的版本仍可能包含有用工具或流程，保留它也就保留了后续修改的起点。基础语言模型、产生修改指令的外层流程和版本选择规则固定，但负责实施修改的程序可以换成先前得到的后代。

## 冻结修改者与取消档案的对照

第一种对照始终让最初的程序负责修改，不让后代接替。其后续收益较早趋缓，支持后代参与修改对所测编程任务的作用。

第二种对照取消历史档案，只沿最新仍可工作的版本继续。它更容易被较差修改阻断；完整系统则能回到其他分支。这项比较检验保留搜索路径的作用，与前一项检验修改者的变化相互补充。

## 编程能力怎样帮助自修改

DGM 利用了解题与自修改之间的技能重合：处理代码问题的能力，也可能帮助程序修改自身。[HyperAgents](hyperagents.md) 将更多改进流程开放为可编辑代码，并检查跨领域迁移后的效果。

DGM 用任务实验评价候选，并保留多个分支继续搜索；原 Gödel machine 要求先证明修改有益。两者分别以经验评价和形式证明作为修改依据。
