# How feedback corrects a learner

Good feedback turns one attempt into evidence for improving the next. Berk–Nash equilibrium, GANs and model collapse explain different parts of this process: **actions determine which evidence is observed, evaluators determine which differences are recognized, and data sources determine what reaches the next generation.** Board games and code show how clear, executable feedback can support learning.

## Berk–Nash Actions determine which beliefs are tested

In a [Berk–Nash equilibrium](../cards/berk-nash.md), beliefs support only the models that best fit the data induced by current actions, while those actions are optimal under the beliefs. Actions select evidence; evidence supports an explanation; that explanation supports the actions.

Even when responses come from the real world, errors about untried actions can persist. If the subjective model class is misspecified, it may also fail to explain observed responses correctly. Exploration expands the range of tests, while model revision expands the explanations available. Together, they determine what real feedback can correct.

## GANs Evaluators determine which differences guide learning

A GAN discriminator sees both real and generated samples. It learns to distinguish their sources and turns the differences into a training signal for the generator. Real samples provide an ongoing reference; the discriminator makes that reference usable.

[Arora and colleagues' results on limited discriminators](../cards/limited-discriminators.md) show that a generated distribution can lack substantial diversity yet remain difficult for a restricted discriminator to distinguish. Alongside Berk–Nash's analysis of evidence selection, this raises another question: once evidence is available, can the evaluator recognize the differences that matter? More samples and greater discriminating ability improve different parts of the process.

## Model collapse Data sources determine how errors are inherited

[Model collapse](../cards/model-collapse.md) concerns successive models learning from samples generated by their predecessors. Finite sampling can omit rare events, leading later models to assign them still less probability. Fitting errors also travel through the changing data source.

Compared with continued access to world responses or real samples, replacing data each generation changes the basis for correction itself. [Research on data accumulation](../cards/data-accumulation.md) changes this error transmission by retaining original and historical data. These three strands let us examine feedback coverage, discriminating ability and provenance together.

## Board games Rules and search provide training targets

Board games such as chess, shogi, and Go offer strong feedback: rules are explicit, state transitions can be computed, and final outcomes can be checked. AlphaZero uses its current network to estimate moves and position values, then uses tree search to choose actions. After each game, the network is trained to predict the rule-determined outcome and the move distribution produced by search. The updated network returns to self-play.

The system generates its own games, but the rules determine the results. Search combines multi-step simulations with network estimates; training turns some of that search experience into cheaper future judgments. Self-play can therefore generate repeated experience, allowing reliable outcome feedback and additional computation to support learning together.

Knowing the rules does not mean having computed all their consequences. Progress in board games can come from computing, accumulating and reusing those consequences, illustrating how computation makes existing knowledge more useful.

## Code Execution makes candidates testable

Code offers another strong feedback setting. Candidate programs can be compiled and tested, producing explicit outcomes such as compilation errors, runtime errors, failed tests and passed tests. CodeRL trains a critic on these outcomes and uses it to turn execution feedback into signals for training the generator.

During generation, CodeRL also uses example tests to filter candidates, selects prefixes with the critic, and generates again. Its experiments compare training signals and the regeneration step separately: the training ablations support using critic-derived weights for individual code tokens, while the regeneration comparison shows that candidate sets more often contain a program that passes the tests. This separates two sources of improvement: learning from execution feedback, and using checks to revise candidates during generation.

Compilation and testing provide explicit, repeatable checks for specified requirements. The model proposes a program, execution produces a result, and learning uses successes and failures to guide later generation. This adds an executable route for correction beyond asking the model to score its own code.

## Connecting feedback to recursive improvement

Board games and code make the productive role of feedback clear: outcomes have explicit grounds, attempts can be repeated, and experience can improve subsequent choices. Berk–Nash, GANs and model collapse help distinguish the parts of this process.

RSI asks whether a system can also improve how it obtains, interprets and uses feedback. [Plasticity research](../cards/plasticity.md) concerns the capacity to keep learning from experience. [STOP](../cards/stop.md) and [HyperAgents](../cards/hyperagents.md) bring the programs that produce modifications into the learning process. Feedback can thus evaluate current behavior and guide improvements to the mechanisms of future learning.
